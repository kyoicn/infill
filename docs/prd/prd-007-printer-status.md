# PRD-007：打印机状态与每日利用率监测

> 本 PRD 与 [PRD-004 系统配置](prd-004-settings.md) 是**上下游关系**：本 PRD 在「打印机管理」的台账之上**扩展凭证字段**（IP / 序列号 / 访问码），并新增一张「打印机状态」页消费这些凭证。PRD-004 的「打印机管理」卡片（[prd-004 CUJ-1](prd-004-settings.md#cuj-1管理打印机)）继续承担**新增 / 删除**的台账操作；本 PRD 给每行**补一个「编辑」按钮**，点开弹窗内修改名称 + 三凭证字段。**本 PRD 同时关闭 PRD-004 差异 #6**（"打印机改名缺 UI 入口"）—— 这个差异不再需要在 PRD-004 侧单独处理，落地由本 PRD CUJ-1 的「编辑」按钮承担。PRD-004 自身是 backfill 类型、以代码现状为准，不需修改其文件。
>
> 与 [docs/prd/index.md](index.md) 「明确不做：打印机实时监控」一行的措辞调整：**不做硬件层深度遥测（温度 / 层数 / 进度百分比 / 摄像头），但做局域网层面「是否在打印」的状态监测与每日利用率统计**。index.md 同步更新此口径。

## 功能概述

作坊主当前 4 台 Bambu Lab（拓竹）打印机都在同一局域网内运转。日常痛点：作坊主想知道**此刻每台机在不在打**（要不要去拿活、要不要补料）以及**每台机每天用了多少**（24h 中工作多少分钟，反映排班是否吃满产能）。当前系统完全不监测打印机，全靠用肉眼跑过去看 LCD。

本 PRD 用 Bambu Lab 本地 MQTT 协议（端口 8883，TLS，需要 IP + serial + access_code 三件套）监听每台打印机的 `device/{serial}/report` 主题，把 `print.gcode_state` 字段映射为「在工作 / 空闲 / 离线」三态并落库；新增一张「打印机状态」页，4 张卡片每张展示当前状态徽章 + 今日已工作时长 + 24h 时间轴 bar。

**MVP 极简口径**（不要扩展）：

- 只看「当前状态」+「今日利用率」；不做告警、不做每周 / 每月报表、不做历史回填、不做远程控制、不做温度 / 层数 / 进度 / 摄像头展示。
- 数据源是本地 MQTT 推送 + 固定间隔采样（30s 一条），从功能上线那天开始统计，**不回填历史**。
- 守护进程是 FastAPI lifespan 启动时为每台已配置凭证的打印机起一个 MQTT 订阅；进程退出清理。**没有持久化重连状态**，崩了重启从零开始；丢的样本可接受。
- 利用率分母固定 **自然日 24h（1440 分钟）**，分子 = 当天 RUNNING/PAUSE 累计分钟数，**按服务器本地时区**切日。
- 未填全凭证的打印机：状态页显示「未配置」卡片，不订阅、不计采样。

本 PRD 范围：

- CUJ-1：配置打印机网络凭证（在 PRD-004 的打印机表单扩展三字段；新增打印机时可填，已存在打印机可补填 / 改）
- CUJ-2：查看打印机状态页（4 张卡片 + 状态徽章 + 今日工作时长 + 24h 时间轴 bar）

**不在本 PRD 范围**（如未来要做需单开 PRD 或扩展本 PRD）：

- 告警 / 推送通知（打印中断 / 长时间空闲提醒）
- 历史利用率趋势（7 天 / 30 天滚动）—— 数据已落库，做视图层即可，但 MVP 不做
- 远程控制（暂停 / 取消 / 启动）
- 硬件层深度遥测（温度 / 层数 / 进度百分比 / 摄像头）
- 任务与排班关联（把状态样本回写到 PrintTask 状态机）—— 当前 PRD-003 排班的批次执行状态仍是手动 confirm，本 PRD 不打通此环

## 数据模型

新增 `printer_status_sample` 表（采样存储），并扩展现有 [Printer 表](../../backend/app/models.py#L117-L121) 三个凭证字段：

| 表 / 字段 | 类型 | 说明 |
|---|---|---|
| `Printer.ip` | `String(64), nullable=True` | 局域网 IP，如 `192.168.1.123`。可空（未配置即 NULL，状态页显示「未配置」） |
| `Printer.serial` | `String(32), nullable=True` | Bambu 打印机序列号，如 `01P00A123456789`。MQTT 主题 `device/{serial}/report` 用 |
| `Printer.access_code` | `String(16), nullable=True` | 访问码（LCD → 设置 → 网络 → 访问码取得），8 位数字字符串。**敏感凭证（能远程控制打印机）**，单用户本地部署不加密存数据库，但**勿提交真值到 git** |
| `printer_status_sample.id` | `Integer PK` | |
| `printer_status_sample.printer_id` | `Integer FK → printers.id` | 级联删（删打印机时清除其样本） |
| `printer_status_sample.ts` | `DateTime, indexed` | 采样时刻（服务器本地时间） |
| `printer_status_sample.state` | `String(16)` | 标准化后的状态：`running` / `pause` / `idle` / `offline` （详见下表映射） |

`print.gcode_state`（来自 Bambu 推送）→ 标准化状态 → 工作分钟统计的映射规则：

| Bambu `gcode_state` | 标准化 `state` | 计入「今日工作分钟」 |
|---|---|---|
| `RUNNING` | `running` | 是 |
| `PAUSE` | `pause` | 是 |
| `IDLE` / `PREPARE` / `FINISH` / `FAILED` / 其他已知状态 | `idle` | 否 |
| MQTT 连不上 / 超时 / 凭证错误 | `offline` | 否 |
| 凭证未配置（三字段任一为 NULL） | 不订阅、不写样本 | 否（状态页显示「未配置」） |

采样写入策略：

- **事件驱动**：收到 MQTT 推送且 `print.gcode_state` 与上次记录的状态**不同**时立刻写一条。
- **定时心跳**：每 30 秒为每台打印机写入一条「当前状态」样本（即便状态没变），以便利用率计算插值不至于在长时间稳态下出现长空段。
- **离线检测**：若守护进程对某台机连续 ≥60 秒未收到任何 MQTT 推送 → 写一条 `state='offline'` 样本，状态徽章切「离线」。重新收到推送时再写一条恢复样本。

利用率计算口径（CUJ-2 渲染时直接查 `printer_status_sample`）：

- 取「今天 00:00（本地）→ 现在」时间窗内该打印机的全部样本，按 `ts` 升序。
- 相邻两条样本之间的时间段，归属为**前一条样本的 state**（线段插值）。
- 当前最后一条样本到「现在」之间，归属为该最后一条样本的 state（最右段持续到现在）。
- 把 state ∈ {`running`, `pause`} 的段累加得到分子（分钟），分母固定 1440。
- 当天**没有任何样本**（功能上线第一天 / 凭证刚填好还没采到数据）→ 利用率显示 `0 / 1440 分钟（0%）`，时间轴 bar 全灰。

## API 契约

| 方法 + 路径 | 请求 → 响应 | 说明 |
|---|---|---|
| `GET /api/printers` | → `list[PrinterOut{id,name,ip,serial,access_code_masked}]` | **扩展现有接口**：返回结构追加三字段；`access_code_masked` 形如 `****1234`（只显示末 4 位，避免凭证泄露到日志 / 截图）。`ip` / `serial` 明文返回（前端编辑表单需要回填） |
| `POST /api/printers` | `PrinterCreate{name, ip?, serial?, access_code?}` → `PrinterOut` | **扩展现有接口**：三字段全部可选。任一为空即视为「未配置」，不订阅 MQTT |
| `PUT /api/printers/{id}` | `PrinterUpdate{name, ip?, serial?, access_code?}` → `PrinterOut` | **扩展现有接口**：用于补填 / 修改凭证 / 改名。**改成功后须触发守护进程重新订阅该机**（详见 CUJ-1 Journey Steps） |
| `GET /api/printers/status/snapshot` | → `list[PrinterStatusOut]` | **新增（REST 快照）**。每台打印机一条：`{printer_id, name, state, today_working_minutes, today_total_minutes:1440, last_state_change_ts, timeline:[{start_minute, end_minute, state}, ...]}`。`state` ∈ {`running`,`pause`,`idle`,`offline`,`unconfigured`}（`unconfigured` 仅在响应里出现，不会落库为样本）。`timeline` 以「今天 0:00 起的分钟数」为单位，描述 24h 时间轴上各段所处状态，前端直接画 bar。**调用时机**：前端首次 mount 时拉一次填充初始内容；WebSocket 断线重连成功后再拉一次补齐错过的事件 |
| `WS /api/ws/printers/status` | server → client：增量事件 `{printer_id, state, ts}`；client → server：周期性 `ping` 心跳 | **新增（WebSocket 推送）**。后端拿到 MQTT 状态变更后扇出推送给所有已连接客户端；前端收到事件就地更新对应卡片的状态徽章 + 时间轴 bar 末段 + 今日工作时长。无业务消息时双向 `ping/pong` 维持连接活性（间隔由实现决定）。客户端断线后用**指数退避**自动重连 |

无单独的「触发重连」接口 — 守护进程在 `PUT /api/printers/{id}` 成功后内部触发重订阅；前端状态页通过 WebSocket 收实时事件、REST snapshot 兜底首次填充与断线补齐（详见下节「数据流 / 实时通道」）。

## 数据流 / 实时通道

整条链路两段，**两段都是推送、不轮询**：

```
打印机 ──MQTT push──▶  后端守护进程  ──WebSocket push──▶  前端状态页
                       │
                       └──写 printer_status_sample（用于利用率累计）
```

**第一段：打印机 → 后端（MQTT，事实非选择）**

- Bambu broker 跑在每台打印机本机 `8883/TLS`，需 IP + serial + access_code 三件套握手。
- 后端 lifespan 启动时为每台三字段非空的打印机起一个 `paho-mqtt`（或等价库）客户端，订阅 `device/{serial}/report`。
- 打印机持续 push；后端 `on_message` 回调被动收，**不主动 poll**。
- 收到状态变更后**两条路并行**：
  - 一条**写库** — 落 `printer_status_sample`，用于利用率累计与时间轴渲染。
  - 一条**进内存 broadcaster**（`asyncio.Queue` / `set` of WebSocket clients，由实现决定）— 立刻扇出给所有连着的 WebSocket 客户端。

**第二段：后端 → 前端（WebSocket）**

- 前端状态页 mount 时按顺序：
  1. `GET /api/printers/status/snapshot` 拉首次快照，渲染 4 张卡片。
  2. 打开 `WS /api/ws/printers/status` 连接。
  3. 后续完全由 WS 事件驱动卡片更新；snapshot 不再周期性拉。
- 后端收到 MQTT 状态变更 → broadcaster 扇出 `{printer_id, state, ts}` → 所有已连接前端就地 patch 对应卡片：
  - 状态徽章按 `state` 重新着色。
  - 今日工作时长按 `ts - last_state_change_ts` 累加（前端本地累加，避免每条事件都重算全量）。
  - 时间轴 bar 末段从 `last_state_change_ts` 延展到 `ts`，新颜色起点设为 `ts`。
- **心跳**：双向 `ping/pong`（具体方向与间隔由实现决定，目的是防代理超时 + 检测半开连接）。
- **重连**：WS 断开 → 前端**指数退避**重连（如 1s → 2s → 4s → 最长 30s 上限）→ 重连成功后**立即拉一次** `GET /api/printers/status/snapshot` 补齐断线期间错过的事件 → 继续走 WS 增量。
- **降级**：
  - WS 重连屡次失败（如代理不支持 WS、网络故障）→ 状态页右上角文案变红色「实时连接断开，X 秒前 snapshot」，状态徽章 + 利用率仍显示最近一次 snapshot 的内容，**不会整页挂掉**。
  - 用户手动刷新页面或重新进入路由 → 重走 mount 流程（snapshot + WS）。

## CUJ-1：配置打印机网络凭证

**Dependencies**: PRD-004 CUJ-1（管理打印机 — 本 CUJ 在其新增 / 编辑表单上扩展三字段）
**Priority**: P0（无凭证则 CUJ-2 无数据可显示，整张状态页空转）

### Context

作坊主拿到 4 台 Bambu Lab 打印机后，要先把每台的 IP / 序列号 / 访问码填进系统，监测才能生效。访问码在打印机 LCD → 设置 → 网络 → 访问码可见（8 位数字）；IP 在 LCD 网络页可见；序列号在 LCD 关于页或机身贴纸可见。一次性配完一般 5 分钟搞定，后续只在打印机重置网络或访问码改变时需要回来更新。**没填全三字段的机器在状态页上显示「未配置」卡片**，不订阅、不计采样。

### Preconditions

- 用户已打开「系统设置」页（PRD-004）。
- 后端 `Printer` 表已迁移加上 `ip` / `serial` / `access_code` 三字段（首次部署 / 升级时执行）。
- 用户手头有打印机 LCD 上的 IP / 序列号 / 访问码三项信息。

### Journey Steps

1. **用户操作**：在系统设置页 → 「打印机管理」卡片，点已有某行右侧的「编辑」按钮（**注**：当前 PRD-004 CUJ-1 没有 UI 改名入口；本 PRD 要求把这个入口补出来，复用既有的 `PUT /api/printers/{id}` 接口）。
   - **系统响应**：打开「编辑打印机」弹窗，从该机已有数据预填表单。
   - **用户看到**：弹窗内四个输入字段，纵向排列：
     - `名称`（已预填，例如「1号机」）
     - `IP 地址`（已预填或空，placeholder「如：192.168.1.123」）
     - `序列号 Serial`（已预填或空，placeholder「如：01P00A123456789」）
     - `访问码 Access Code`（**密码框样式**，预填时显示 `••••1234` 即末 4 位明文 + 前 4 位掩码点；空时 placeholder「LCD → 设置 → 网络 → 访问码取得」）
     - 字段下方一段灰色帮助文字：「IP / 序列号 / 访问码三项全填才会启动监测；任一为空显示『未配置』。访问码勿外传。」
     - 弹窗底部：「确定 / 取消」按钮。
   - **Details**：访问码密码框带「眼睛图标」可一键明文显示（点一下切换 type=password / text）。前端预填时如果后端只返回了 `access_code_masked`，则点眼睛展示也只能看到掩码尾 4 位 — 用户**重新输入完整值**才能改；输入框为空意味着「不修改」（保留旧值），用户清空后再保存视为「清掉这台机的凭证」。

2. **用户操作**：填入 IP / 序列号 / 访问码三项，点「确定」。
   - **系统响应**：前端调用 `PUT /api/printers/{id}`，请求体含四字段（名称 + 三凭证）。`access_code` 字段：用户没改过密码框（仍是掩码态）→ 前端**不发送** `access_code` 字段（请求体省略此 key，后端理解为「保留旧值」）；用户清空或重填 → 发送新值（含空串语义为清掉）。后端 upsert 成功后：(a) 若三字段在保存后**全部非空** → 通知守护进程对该 `printer_id` 重新订阅 MQTT；(b) 若任一字段保存后为空 → 通知守护进程取消订阅该机并把其状态徽章切回「未配置」。前端 `message.success('已保存')` 并刷新打印机列表。
   - **用户看到**：弹窗关闭，绿色提示「已保存」，打印机表格行不变（名称未改的话）。状态页（若另开 tab 打开）在守护进程完成重订阅并收到第一条 MQTT 推送后，**通过 WebSocket 实时推送**刷出该机的新徽章（通常 1~3 秒内）。
   - **Details**：守护进程重订阅是内部事件，前端无感；若 MQTT 连接失败（凭证错 / IP 错），状态页随后会把该机徽章切到「离线」。**不在保存时做连通性预校验**，避免拖慢保存交互（连通性结果反馈通过状态页徽章观察）。

3. **用户操作**：（首次配置新打印机的等价路径）在「打印机管理」点「新增打印机」。
   - **系统响应**：现有批量新增弹窗（PRD-004 CUJ-1 Step 2-4）**保持不变**（只输入名称、可批量加多台）。新增之后用户回到表格，对每台机走 Step 1 的「编辑」流程补凭证。**原因**：批量新增是「先把台账填齐」的快路径，凭证每台都不一样、需逐台填，混在批量弹窗里会拖慢心智。
   - **用户看到**：与 PRD-004 CUJ-1 现有行为一致；新增完后表格新行的状态页徽章默认是「未配置」直到用户编辑补齐凭证。
   - **Details**：未来若用户反馈「希望新增时一并填凭证」，可再扩；MVP 走两步式。

### Edge Cases & Error States

- **三字段只填一两个**：保存允许（后端不强制三字段同时非空），但状态页显示「未配置」徽章（同未填）。**已知：不强制原子性，便于用户分次填**。
- **IP 改变（打印机换网段）**：用户编辑改 IP → 保存 → 守护进程立刻重连新 IP。重连失败时该机切「离线」徽章。无连通性预校验提示。
- **访问码错**：保存成功（后端不预校验），MQTT 握手失败 → 守护进程把该机状态置 `offline`、状态页显示「离线」。用户无明确「访问码错」提示，需自己排查。**已知：MVP 不区分"网络不通"和"凭证错"，统一显示『离线』**；未来可在状态卡片悬浮 tooltip 里加一行「最近一次连接失败原因」。
- **清空凭证**：用户编辑把任一字段清空再保存 → 守护进程取消订阅该机、状态页切「未配置」。
- **删除打印机**（PRD-004 CUJ-1 现有删除按钮）：后端先取消该机的 MQTT 订阅再删 `Printer` 行；`printer_status_sample` 通过外键级联删除。
- **重启 backend**：进程内的 MQTT 客户端全部丢失，重启时 lifespan 重新对全部三字段非空的打印机起订阅；订阅恢复期间（一般 1~3 秒）状态页显示「离线」徽章，恢复后切回真实状态。**已知：进程崩溃 / 重启期间会丢若干秒的样本**。
- **访问码泄露风险**：日志里**禁止打印访问码原值**（守护进程的连接日志只打 `printer_id` + IP + masked code）；API 响应统一返回 `access_code_masked`（仅 4 位明文）。**不要把含真值的数据库 dump 提交到 git**（开发自查项）。

### 验收标准

- 打印机表格每行有一个「编辑」按钮，点击打开含名称 + IP + 序列号 + 访问码四字段的弹窗。
- 访问码字段为密码样式，预填时仅显示末 4 位明文 + 掩码点；用户未改动密码框点保存时，后端记录的访问码保持不变。
- 保存非空 IP + serial + access_code 后，10 秒内 `GET /api/printers/status/snapshot` 返回的对应机状态从 `unconfigured` 切到 `running` / `idle` / `offline` 之一。
- 把某机的 IP 字段清空保存后，下次 `GET /api/printers/status/snapshot` 返回该机状态为 `unconfigured`，状态页徽章切「未配置」。
- 删除打印机后，`printer_status_sample` 表里该 `printer_id` 的样本全部消失（外键级联生效）。
- 应用日志（含 ERROR 级 stack trace）中不出现访问码原值字符串。

## CUJ-2：查看打印机状态页

**Dependencies**: CUJ-1（无凭证则无数据）
**Priority**: P0（本 PRD 的主交付）

### Context

作坊主在打印工作日想随手看一眼「哪几台还在打、哪几台空着、今天产能跑得怎么样」。状态页是一张**为这个查看动作专门优化**的页：进来一眼就看清 4 台机当前状态 + 今日工作时长，不需要点击展开。页面只读、不带操作按钮，定位是「监控仪表盘」。

### Preconditions

- 用户至少有 1 台已在 PRD-004 录入的打印机（未必填了凭证）。
- 后端守护进程已对全部三字段非空的打印机起 MQTT 订阅（lifespan 启动后立即生效）。

### Journey Steps

1. **用户操作**：从主导航点「打印机状态」（新菜单项，位于 Dashboard 与「系统设置」之间）。
   - **系统响应**：进入路由 `/printers/status`，**按序执行两步**：(a) 立刻调 `GET /api/printers/status/snapshot` 获取首次快照；(b) 打开 `WS /api/ws/printers/status` WebSocket 连接订阅增量事件。Snapshot 返回后渲染 4 张卡片初始内容；WS 建连成功后由实时事件驱动后续更新。
   - **用户看到**：页面顶部标题「打印机状态」，右上角一行小字状态指示：
     - 绿色「实时连接中」：WS 已连且最近收到心跳。
     - 黄色「重连中…」：WS 断开、指数退避重连中。
     - 红色「实时连接断开，X 秒前 snapshot」：WS 重连屡次失败，已降级为只看 snapshot 时刻数据。
   - 下方一个**4 列响应式网格**（屏宽 < 992px 时 2 列，< 576px 时 1 列），每张卡片一台打印机。**无打印机**时显示空态：「暂无打印机，请先到 [系统设置 → 打印机管理](路由 `/settings`) 添加。」
   - **Details**：snapshot 失败（网络抖 / 后端挂）→ 整页空态显示「连接失败」+ 「重试」按钮；snapshot 成功但 WS 失败 → 卡片正常显示 snapshot 内容，右上角红色文案提示降级。

2. **用户操作**：查看某张卡片。
   - **系统响应**：卡片以纯展示方式渲染（无点击交互）。
   - **用户看到**：单张卡片版式（约 320×220）：
     - 左上：打印机名称（如「1号机」，16px 粗体）
     - 右上：状态徽章（圆角胶囊，4 种配色）：
       - `打印中` — 绿底白字，左侧小圆点动画呼吸
       - `暂停` — 黄底深字
       - `空闲` — 灰底深字
       - `离线` — 红底白字
       - `未配置` — 浅灰底中灰字 + 一个齿轮图标，悬浮 tooltip「点击右上角『设置』补填 IP/序列号/访问码」
     - 中部一行大字：`今日已工作：X 小时 YY 分 / 24 小时`（13 → `13 小时 00 分 / 24 小时`；不足 1 小时显示 `X 分 / 24 小时`）；其下一行灰色小字：`利用率 ZZ.Z%`（保留 1 位小数）
     - 底部 24h 时间轴 bar（占满卡片宽度，高 24px）：
       - 时间刻度：底部对齐有 5 条短刻度文字 `0` `6` `12` `18` `24`
       - bar 主体：横向 1440 像素映射到 bar 宽度（按比例缩放），按 `timeline` 数组涂色 — `running` 段绿、`pause` 段黄、`idle` 段灰、`offline` 段红条纹（与「空闲」可视分别）；`unconfigured` 卡片整条 bar 浅灰 + 居中文字「未配置」
       - 当前时刻位置画一条**深色细竖线**指示「现在」
       - 鼠标悬浮 bar 上任意像素：tooltip 显示该位置对应的 `HH:MM` + 当时状态
   - **Details**：卡片不接受点击；状态徽章配色与排班甘特图（PRD-003）的状态色风格保持一致。卡片之间垂直间距 16px，水平间距 16px。

3. **用户操作**：保持页面打开，时间流逝。
   - **系统响应**：WebSocket 持续接收 `{printer_id, state, ts}` 增量事件；前端就地 patch 对应卡片状态徽章 + 利用率累计 + 时间轴 bar 末段。无状态变化时打印机仍以 30s 心跳样本兜底，前端只在收到「状态实际变化」事件时重绘徽章，否则只延展末段 bar 颜色。
   - **用户看到**：徽章颜色无闪烁切换（淡入淡出 200ms 过渡）；时间轴 bar 右端那段随时间向右延展（每秒钟刷一次本地累计，不依赖事件频率）；右上角「实时连接中」绿点稳态显示。
   - **Details**：增量更新用 React state 浅 diff，避免整卡片重绘抖动。**WS 断开 → 重连成功后**自动拉一次 `GET /api/printers/status/snapshot` 补齐错过的事件，再继续走 WS 增量；用户视觉上仅短暂看到右上角文案在「重连中…」与「实时连接中」之间切换，卡片内容平滑校正。

### Edge Cases & Error States

- **打印机 0 台**：显示「暂无打印机」空态，链接跳系统设置。
- **打印机全部未配置**：4 张「未配置」卡片，时间轴 bar 全灰，每张悬浮 tooltip 提示去补凭证。
- **某机 MQTT 刚启动还没收到推送**：状态徽章显示「离线」（守护进程视为「未确认在线」），有第一条推送进来后立刻切真实状态。**已知：首次连接窗口（≤3 秒）会有短暂"离线"假象**。
- **服务器跨午夜时**：跨 0:00 时，原卡片今日工作时长一夜 0 重置（新自然日开始）。如果用户页面开着跨了午夜，下一次 WS 状态事件或前端本地午夜定时器（由实现决定）触发卡片归零重算，**无显式提示「日切换了」**。
- **时间轴 bar 上某段太短（< 1 像素）**：渲染最小可见宽度 1 像素，避免被四舍五入吞掉（否则短打印任务可视化丢失）。
- **离线段过长**：若某机长时间离线（如断电拔网），时间轴红条纹大段铺开；状态徽章红底「离线」。这是预期行为，不弹通知。
- **守护进程 MQTT 客户端故障**：后端日志记录 ERROR；前端表现等同「离线」。无前端可见的「后端故障」提示。**已知：MVP 不暴露守护进程健康度**。
- **WebSocket 重连屡次失败**（代理不支持 WS、网络中断等）：右上角红色文案「实时连接断开，X 秒前 snapshot」，每张卡片仍展示最近一次 snapshot 时刻的状态徽章与今日利用率；时间轴 bar 末段停在 snapshot 时刻；用户刷新页面会重走 mount 流程并再次尝试连 WS。
- **WebSocket 短暂闪断**（如代理 idle timeout 踢断）：前端指数退避重连（1s/2s/4s…/30s 上限），重连成功后立刻拉一次 `GET /api/printers/status/snapshot` 补齐错过的状态变更；用户视觉上看到右上角文案短暂切到「重连中…」再回绿。
- **后端进程重启**：所有连接的 WS 客户端会收到断开 → 自动重连到新启动的进程；新进程 lifespan 完成 MQTT 订阅 + WS 端点就绪后，前端 snapshot 拉取也恢复，整页在 ≤10~30s 内回到实时。
- **当天工作时长超过 24h（理论不会）**：渲染时 `min(today_working_minutes, 1440)` 截断，避免百分比 >100%。

### 验收标准

- 主导航有「打印机状态」入口，点击进入 `/printers/status`。
- 每台已在 `Printer` 表的打印机对应一张卡片，**不论凭证是否配齐**。
- 凭证齐全的打印机卡片正确显示徽章（打印中 / 暂停 / 空闲 / 离线）、今日工作时长、利用率百分比、24h 时间轴 bar。
- 凭证未齐全（任一字段为空）的打印机卡片显示「未配置」徽章 + 灰色时间轴。
- 时间轴 bar 上 `running` 段为绿色、`pause` 段为黄色、`idle` 段为灰色、`offline` 段为红色条纹。
- 时间轴 bar 上画有一条深色竖线指示「现在」时刻。
- 页面 mount 时先调一次 `GET /api/printers/status/snapshot`，随后通过 `WS /api/ws/printers/status` 接收实时增量事件；右上角显示「实时连接中 / 重连中 / 实时连接断开」三态指示。
- 在打印机端手动操作一次「开始打印」，**1 秒内**状态页对应卡片徽章变为「打印中」（验证 WebSocket 实时通道生效）。
- 主动断开 WebSocket（如杀掉后端进程再重启）→ 前端按指数退避自动重连 → 重连成功后立即拉一次 `GET /api/printers/status/snapshot` → 卡片状态与服务端一致（验证重连 + snapshot 补齐）。
- 把某打印机的 access_code 改错后保存，**该机的徽章在 ≤30 秒内**切换到「离线」。
- 把某离线打印机的 access_code 改回正确值并保存，**该机的徽章在 ≤30 秒内**切回真实状态（打印中 / 空闲 / 暂停）。
- 后端进程重启后，所有凭证齐全的打印机在 ≤10 秒内被重新订阅，状态卡片在 ≤30 秒内显示真实状态。
- 利用率分子从「今天 00:00（服务器本地时区）」开始累计；跨午夜后下一次 WS 事件 / snapshot 自动归零重算。

## 关键约束 / 风险（汇总）

| # | 描述 | 影响 |
|---|---|---|
| 1 | MQTT 守护进程**无持久化重连状态** | 后端重启后丢失订阅状态；重启期间（一般 1~10 秒）所有卡片显示「离线」假象 |
| 2 | 利用率按**服务器本地时区**自然日切片 | 部署机时区改动需谨慎，会破坏统计连续性；未做时区可视化提示 |
| 3 | `access_code` 是**敏感凭证**（能远程控制打印机）| 不加密落库（单用户本地部署可接受），但 API 响应 / 日志 / Git 提交均不得包含明文真值 |
| 4 | **不区分「网络不通」与「访问码错」** | 用户排查凭证问题时只能看见「离线」，需自查 |
| 5 | **不回填历史**，从功能上线日开始统计 | 上线第一天利用率均为 0；与历史无对照 |
| 6 | MQTT 推送频率不可控 | 用 30s 心跳兜底确保线段插值不出现长空段；但若打印机短时间内频繁切状态，可能有 ≤30s 粒度的统计误差 |
| 7 | 凭证「未配置」与「凭证错（离线）」是两种不同徽章 | 用户区分两类问题；「未配置」点击徽章悬浮 tooltip 引导去补填 |
